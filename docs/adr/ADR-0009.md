# ADR-0009 — Portar os componentes do design system sob demanda

**Status:** Aceito — prop surface revista pelo [ADR-0010](ADR-0010.md)
**Data:** 2026-08-31

## Contexto

O ADR-0003 trouxe os _tokens_ do design system e deixou os 24 componentes de
fora, registrando que portá-los seria decisão própria. Esta é a decisão.

Os componentes na origem são `.jsx` com `.d.ts` ao lado, escritos para um
ambiente de protótipo: importam `React` global, e o kit de telas os consome por
`window.DOCIntelligenceDesignSystem_8541ef`. Nada disso roda no App Router sem
tradução.

## Decisão

**Portar só o que cada tela usa, quando ela usa.** Não os 24 de uma vez.

Esta tela trouxe sete:

```
components/core/{Icon,Button,Card}.tsx
components/feedback/{ProgressBar,Toast}.tsx
components/documents/{DropZone,FileThumb}.tsx
components/index.ts          — a superfície pública
```

As pastas espelham as da origem, para que re-sincronizar seja comparar arquivo
com arquivo.

`components/index.ts` existe porque a origem proíbe importar componente por
caminho interno (`no-restricted-imports` no `_adherence.oxlintrc.json`). Telas
importam de `@/components`.

## Por quê sob demanda

- **Portar 17 componentes não usados seria código não exercitado.** Nenhuma tela
  os renderiza, nenhum teste os cobre, e cada um carrega uma tradução de JSX
  para TSX que ninguém conferiu. Eles chegam quando a tela que os pede chegar.
- **O escopo são 3 telas, o design system cobre 5.** `SidebarNav`, `Tabs`,
  `Pagination` e `SearchField` servem principalmente conferência e busca, que o
  `AGENTS.md` põe fora do escopo sem confirmação explícita.

## Fidelidade: o que mudou e o que não

> **Revisto pelo [ADR-0010](ADR-0010.md):** `style` deu lugar a `className`, e
> `Card` perdeu a prop `padding`. O resto segue valendo.

**Prop surface inalterada** em todos os sete. Uma tela escrita contra o
componente original continua válida — os nomes, os valores aceitos e os padrões
são os mesmos. Isso importa porque as regras de aderência da origem checam
exatamente isso (`<Button variant>` só aceita `primary|inverse|danger|outline|ghost`,
e assim por diante), e agora os `.d.ts` portados dão a mesma garantia em tempo
de compilação — mais forte que o lint.

Quatro desvios, todos deliberados:

1. **`Icon` inlina os SVGs do Lucide em vez de buscá-los de
   `unpkg.com/lucide-static`.** Mesma troca que o ADR-0003 fez com as fontes:
   some uma requisição a terceiro no runtime. Ganho colateral: um `<img>` não
   herda `currentColor`, e por isso a origem tinta os glifos com `filter`
   (inclusive um `ICON_RED` que aproxima `--red-500` por tentativa e erro). Com
   SVG inline o glifo usa `currentColor` de verdade, e `light`/`color` viram
   props honestas. Só os 9 glifos usados estão lá; adicionar um é copiar os
   paths do `lucide-static` na versão fixada — **não desenhar à mão**.

2. **`ProgressBar` não declara mais as keyframes num `<style>` interno.** Na
   origem, cada instância montada renderiza a mesma regra CSS de novo. Elas
   passaram para `styles/design-system/keyframes.css`, uma vez para o app todo.

3. **`Button` não tem a prop `as`.** A origem permite `as="a"` para renderizar
   link. Nenhuma tela desta entrega precisa, e um componente polimórfico correto
   em TypeScript custa bem mais do que aparenta. Entra quando houver botão-link.

4. **`FileThumb` usa `<img>`, não `next/image`.** O `src` é um `blob:` de
   `URL.createObjectURL`, que o otimizador de imagem do Next não consegue buscar
   nem cachear. O `eslint-disable` está na linha, com o motivo escrito.

## Alternativas descartadas

- **Portar os 24 de uma vez.** Foi a opção (a) que ofereci quando o design
  system entrou, e ficou sem resposta. Na dúvida, o `AGENTS.md` (regra 4) manda
  não implementar "a versão mais completa possível" por padrão.
- **Consumir o `_ds_bundle.js` direto.** É um bundle IIFE que pendura tudo em
  `window` e presume React global. Não há tipos em runtime, não funciona em
  Server Component, e o `"use client"` teria de envolver o app inteiro.
- **Copiar os `.jsx` e deixar o `allowJs` do tsconfig resolver.** Perderia todos
  os tipos justamente nos componentes onde a aderência importa, e é onde os
  `.d.ts` da origem têm mais valor.
- **Publicar o design system como pacote npm interno.** Certo num time com
  várias aplicações. Aqui seria infraestrutura para um consumidor só.

## Custo de reverter

Baixo por componente — cada arquivo é independente e a superfície de props é a
da origem, então trocar a implementação não toca em quem os usa.
