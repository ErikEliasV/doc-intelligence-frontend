# ADR-0001 — Baseline da stack: Next.js 16, não 14

**Status:** Aceito
**Data:** 2026-08-31

## Contexto

O pedido foi "Next.js 14+ com TypeScript, App Router e Tailwind CSS". O projeto
já tinha sido inicializado antes desta sessão. A verificação encontrou:

| Item       | Pedido | Encontrado                                                |
| ---------- | ------ | --------------------------------------------------------- |
| Next.js    | 14+    | **16.3.3**                                                |
| React      | —      | 19.2.8                                                    |
| TypeScript | sim    | 5.x, `strict: true`                                       |
| App Router | sim    | sim (`app/layout.tsx`, `app/page.tsx`)                    |
| Tailwind   | sim    | **v4** (`@tailwindcss/postcss`, sem `tailwind.config.js`) |
| ESLint     | —      | 9.x, flat config                                          |

Ou seja: o requisito "14+" está satisfeito, mas por uma margem grande o
suficiente para mudar como se escreve código.

## Decisão

Manter a versão instalada. Não fazer downgrade para a linha 14.

## Consequências

O que muda em relação ao Next.js 14, e que precisa ser levado em conta em toda
tela futura:

- **Tailwind v4 não tem `tailwind.config.js`.** A configuração de tema é CSS,
  via `@theme` em `app/globals.css`. Isso determinou a forma da integração do
  design system (ver ADR-0003).
- **Turbopack é o bundler do build**, não só do dev.
- **Tipos de rota gerados.** `app/layout.tsx` usa `LayoutProps<"/">`, um tipo
  global que o Next gera — não a assinatura manual `{ children: React.ReactNode }`
  que a maior parte da documentação antiga mostra.
- **A documentação de treino do agente está desatualizada para esta versão.** O
  `AGENTS.md` gerado pelo próprio `next dev` obriga a ler
  `node_modules/next/dist/docs/` antes de escrever código. Essa regra foi mantida
  no topo do arquivo e não deve ser removida.

## Alternativas descartadas

- **Downgrade para Next.js 14.** Descartado: o pedido diz "14+", nada obriga a
  usar exatamente a 14, e um downgrade custaria retrabalho em `layout.tsx`,
  na configuração do Tailwind e no ESLint flat config — sem nenhum ganho.

## Custo de reverter

Alto. Um downgrade agora implicaria reescrever a configuração do Tailwind (v4 →
v3, CSS → JS), a assinatura do root layout e o ESLint. Não há motivo previsto
para fazer isso.
